# Проверки

Две штуки. Первую можно гонять всегда, вторая требует базу.

## Статические — без базы, без сети, без ключей

```
python3 tests/check_static.py
```

Секунда работы. Проверяет то, что ломается молча и замечается только через
неделю по жалобе пользователя:

- каталог разборов сходится сам с собой (нет платного разбора без промпта,
  нет промпта без цены, апселлы не ведут в пустоту);
- все эмодзи-заголовки блоков есть в `header_emoji.py`, внутри одного промпта
  не повторяются, а `ai.py` и `pdf.py` берут список именно оттуда;
- в текстах нет обращений к читателю с указанием пола;
- callback-префиксы кнопок не перехватывают друг друга;
- все админские обработчики проверяют `ADMIN_ID`;
- все эндпоинты кабинета, кроме заведомо публичных, проверяют авторизацию,
  а фронт не зовёт несуществующих маршрутов;
- по обращению-заглушке («дорогой», «дорогая») не считаются числа имени.

Гоняй перед каждым коммитом. Ненулевой код возврата = что-то сломано.

## Денежные — нужен PostgreSQL

```
DATABASE_URL=$(sh tests/pg_start.sh) python3 tests/test_money.py
```

`pg_start.sh` поднимает одноразовую базу в `/tmp` и печатает строку
подключения к ней. Если база уже поднята — просто печатает.

44 проверки: купоны (оба режима, гонки, откат при исчерпанном лимите), баланс,
ежедневный бонус, рефералы, отзывы, подарки, повтор вебхука ЮKassa,
напоминание о продлении премиума и все дневные лимиты.

**На боевую базу не направлять** — скрипт пишет и удаляет строки. В нём есть
проверка на `railway`/`amvera` в строке подключения, но это подстраховка, а не
разрешение не думать.

### Почему тут именно гонки

Все находки в этой части кода были про одновременность: двойной клик по кнопке
оплаты, повторный вебхук от ЮKassa, две открытые вкладки кабинета. Обычный
последовательный вызов функции такие баги не показывает — он проходит зелёным
на коде, который в проде списывает деньги дважды. Поэтому почти каждая
проверка запускает операцию параллельно и смотрит, сколько раз она реально
прошла.

## Что делать, если проверка мешает

Не ослаблять молча. У каждой проверки в докстроке написано, какой реальный баг
она ловит — сначала прочитай его, потом решай. Если проверка правда устарела,
меняй её вместе с докстрокой, чтобы следующий человек понимал новое правило.
