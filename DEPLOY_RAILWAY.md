# Переезд на новый аккаунт Railway

Порядок важен. Пункт 1 нельзя откладывать: пока старый аккаунт жив, база
доступна, а когда он кончится — данные достать может быть уже неоткуда.

## 1. СНАЧАЛА забрать базу со старого аккаунта

Там лежат все пользователи, покупки, готовые разборы, купоны и рефералы.
Код лежит на GitHub, база — нет. Потеряется только она, и восстановить будет
нечем.

В старом проекте Railway: сервис Postgres → Variables → скопировать
`DATABASE_URL` (или `DATABASE_PUBLIC_URL` — снаружи нужен именно публичный).

```
pg_dump "<старый DATABASE_URL>" --no-owner --no-acl -Fc -f evva.dump
```

Проверить, что дамп не пустой:

```
pg_restore --list evva.dump | head
```

Сохранить файл куда-нибудь, где он переживёт всё это — облако, почта себе.
**Пока дампа нет, дальше не идти.**

Если старый аккаунт уже не открывается — скажи, будем думать отдельно;
вариантов мало, но они есть.

## 2. Остановить старого бота

Обязательно ДО запуска нового. Telegram не даёт двум процессам опрашивать
один токен: они начнут выхватывать апдейты друг у друга, часть сообщений
пропадёт, в логах пойдут ошибки конфликта. Выглядит как «бот сходит с ума»,
а причина в этом.

В старом проекте: сервис бота → Settings → Remove (или просто выключить
деплой).

## 3. Новый проект

New Project → Deploy from GitHub repo → `cobinix17/evva-bot`, ветка `main`.

Railway увидит `Dockerfile` и соберёт по нему — там уже стоят системные
библиотеки для PDF и `TZ=UTC`. `nixpacks.toml` и `amvera.yaml` он проигнорирует,
трогать их не надо.

## 4. Postgres и данные

В том же проекте: New → Database → PostgreSQL. Затем залить дамп:

```
pg_restore -d "<новый DATABASE_PUBLIC_URL>" --no-owner --no-acl evva.dump
```

Сверить, что всё доехало — числа должны совпасть со старой базой:

```
psql "<новый DATABASE_URL>" -c "SELECT count(*) FROM users;"
psql "<новый DATABASE_URL>" -c "SELECT count(*) FROM payments;"
psql "<новый DATABASE_URL>" -c "SELECT count(*) FROM generated_readings;"
```

Пока не совпали — старую базу не удалять.

## 5. Переменные окружения

Сервис бота → Variables. `DATABASE_URL` удобнее сослать на базу переменной
`${{Postgres.DATABASE_URL}}` — тогда он не протухнет при пересоздании базы.

| Переменная | Откуда взять |
|---|---|
| `BOT_TOKEN` | @BotFather |
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` |
| `WEBAPP_URL` | домен из пункта 6 |
| `OPENROUTER_API_KEY` | основной ИИ |
| `CEREBRAS_API_KEY` | резерв |
| `GROQ_API_KEY` | резерв |
| `YOOKASSA_SHOP_ID` | оплата картой |
| `YOOKASSA_SECRET_KEY` | оплата картой |

`PORT` Railway подставляет сам.

## 6. Домен

Сервис бота → Settings → Networking → Generate Domain. Получится адрес вида
`что-то.up.railway.app`. Его — в `WEBAPP_URL`, без `/app` на конце, бот
допишет сам. Кнопка Mini App перепривяжется при следующем старте бота.

## 7. ЮKassa — самое дорогое, если забыть

Адрес уведомлений в личном кабинете ЮKassa всё ещё смотрит на старый домен.
Не поменяешь — оплаты картой будут **проходить и деньги списываться, а разбор
человек не получит**: уведомление уйдёт в никуда.

Личный кабинет ЮKassa → Интеграция → HTTP-уведомления:

```
https://<новый домен>/webhook/yookassa
```

Проверить живой оплатой на минимальную сумму сразу после запуска.

## 8. Проверка

- `/start` отвечает;
- открывается Mini App;
- бесплатный калькулятор числа судьбы считает;
- покупка за звёзды проходит, разбор приходит;
- покупка картой проходит, разбор приходит (пункт 7);
- в логах при старте нет строки `дедупликация coupon_uses не выполнена`
  — если она есть, скажи, разберёмся.

Утренняя рассылка (08:00 UTC), пост в канал (07:00 UTC), опрос по пятницам и
напоминание о продлении премиума (09:00 UTC) видно только на следующий день.

## Про новый аккаунт — один раз и без нотаций

$5 — разовый грант новому аккаунту, сгорает через 30 дней. То есть это месяц
отсрочки, а не решение: через месяц будем ровно здесь же, только с ещё одним
переносом базы.

Railway связывает аккаунты по платёжным данным и может заблокировать за
мультиаккаунт. Риск не в потере $5, а в том, что вместе с проектом
пропадёт доступ к базе, где лежат оплаченные разборы живых людей. Поэтому
пункт 1 — дамп — не формальность: с ним худший сценарий это «переехали ещё
раз», без него это «потеряли всё».

Решение твоё, я просто говорю цену.
