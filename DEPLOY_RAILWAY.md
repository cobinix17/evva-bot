# Запуск на новом аккаунте Railway

Вариант с чистой базой: старые данные не переносим.

## 1. Погасить старого бота

Обязательно ДО запуска нового. Telegram не даёт двум процессам опрашивать
один токен: они начнут выхватывать апдейты друг у друга, часть сообщений
пропадёт, в логах пойдут ошибки конфликта. Со стороны выглядит как «бот сошёл
с ума», а причина в этом.

В старом проекте: сервис бота → Settings → Remove (или выключить деплой).

## 2. Новый проект

New Project → Deploy from GitHub repo → `cobinix17/evva-bot`, ветка `main`.

Railway увидит `Dockerfile` и соберёт по нему — там уже стоят системные
библиотеки для PDF и `TZ=UTC`. `nixpacks.toml` и `amvera.yaml` он
проигнорирует, трогать их не надо.

## 3. Postgres

В том же проекте: New → Database → PostgreSQL. Больше ничего делать не нужно:
`init_db` при первом старте сам создаст все таблицы и индексы.

## 4. Переменные окружения

Сервис бота → Variables. `DATABASE_URL` удобнее сослать на базу переменной
`${{Postgres.DATABASE_URL}}` — тогда он не протухнет при пересоздании базы.

| Переменная | Откуда взять |
|---|---|
| `BOT_TOKEN` | @BotFather |
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` |
| `WEBAPP_URL` | домен из пункта 5 |
| `OPENROUTER_API_KEY` | основной ИИ |
| `CEREBRAS_API_KEY` | резерв |
| `GROQ_API_KEY` | резерв |
| `YOOKASSA_SHOP_ID` | оплата картой |
| `YOOKASSA_SECRET_KEY` | оплата картой |

`PORT` Railway подставляет сам.

## 5. Домен

Сервис бота → Settings → Networking → Generate Domain. Получится адрес вида
`что-то.up.railway.app`. Его — в `WEBAPP_URL`, без `/app` на конце, бот
допишет сам. Кнопка Mini App перепривяжется при следующем старте бота.

## 6. ЮKassa — самое дорогое, если забыть

Адрес уведомлений в личном кабинете ЮKassa всё ещё смотрит на старый домен.
Не поменяешь — оплаты картой будут **проходить и деньги списываться, а разбор
человек не получит**: уведомление уйдёт в никуда.

Личный кабинет ЮKassa → Интеграция → HTTP-уведомления:

```
https://<новый домен>/webhook/yookassa
```

Проверить живой оплатой на минимальную сумму сразу после запуска.

## 7. Проверка

- `/start` отвечает;
- открывается Mini App;
- бесплатный калькулятор числа судьбы считает;
- покупка за звёзды проходит, разбор приходит;
- покупка картой проходит, разбор приходит (пункт 6);
- `/admin` открывается — `ADMIN_ID` зашит в `config.py`, так что права
  сохраняются и на пустой базе.

Утренняя рассылка (08:00 UTC), пост в канал (07:00 UTC), опрос по пятницам и
напоминание о продлении премиума (09:00 UTC) видно только на следующий день.

## Что означает пустая база — по пунктам

Не для того, чтобы отговорить, а чтобы не удивляться потом:

- **Купленные разборы пропадают.** Кто заплатил за матрицу или психопортрет,
  откроет «Мои разборы» и увидит пусто. Это первое, из-за чего напишут.
- **Подписчики за звёзды продолжают платить.** Подписка Telegram Stars
  продлевается на стороне Telegram, а не бота. Человек платит 399⭐ в месяц,
  но в новой базе его премиума нет — доступа не будет до ближайшего
  автосписания, на котором бот получит `successful_payment` и восстановит
  подписку сам. То есть до месяца оплачено и не выдано.
- **Реферальные балансы и приглашения обнуляются** — накопленные звёзды
  сгорают.
- **Бесплатный первый разбор снова доступен всем** — `free_used` пустой.
  Это единственный пункт, который работает в плюс: старые пользователи
  получат бесплатный разбор ещё раз.

Если старый проект ещё открывается, дамп снимается за две минуты и ни к чему
не обязывает — можно забрать сейчас и решить позже:

```
pg_dump "<старый DATABASE_PUBLIC_URL>" --no-owner --no-acl -Fc -f evva.dump
```

Восстановить в новую базу можно когда угодно:

```
pg_restore -d "<новый DATABASE_PUBLIC_URL>" --no-owner --no-acl evva.dump
```
