# Переезд на Amvera

Пошагово. Порядок важен: пока не перенесена база, старого бота выключать нельзя,
а два бота одновременно запускать нельзя тем более.

## 0. Что уже сделано в коде

- `amvera.yaml` — сборка тем же `Dockerfile`, порт 8080.
- `Dockerfile` — добавлен `ENV TZ=UTC`, чтобы личный день и личный месяц
  не сдвинулись из-за другого часового пояса площадки.
- Менять в коде больше ничего не нужно: бот работает на long polling
  (`dp.start_polling`), веб слушает `0.0.0.0:$PORT`, `PORT` по умолчанию 8080.

## 1. Создать проект в Amvera

1. Тип проекта — **Приложение**, окружение **Docker**.
2. Способ доставки кода — **Git**: Amvera даёт свой remote вида
   `https://git.amvera.ru/<логин>/<проект>`.
3. Подключить его как второй remote и запушить:

   ```
   git remote add amvera https://git.amvera.ru/<логин>/<проект>
   git push amvera main
   ```

   Railway остаётся на `origin` — пока переезд не закончен, он должен работать.

## 2. Поднять PostgreSQL

В Amvera это **отдельный проект** (Управляемые сервисы → PostgreSQL), не часть
приложения. После создания на вкладке «Инфо» будут `host`, `port`, `user`,
`password`, `dbname`. Хост выглядит примерно как
`amvera-<логин>-cnpg-<имя>-rw`.

Строка подключения для переменной `DATABASE_URL`:

```
postgresql://<user>:<password>@<host>:5432/<dbname>?sslmode=require
```

`sslmode` asyncpg понимает, отдельной настройки в коде не требуется.

## 3. Перенести данные

**Сначала выключить бота на Railway** — иначе покупки и разборы, сделанные между
дампом и переключением, потеряются.

```
# 1. Выключить деплой на Railway
# 2. Снять дамп со старой базы (DATABASE_URL берётся из Railway)
pg_dump "<старый DATABASE_URL>" --no-owner --no-acl -Fc -f evva.dump

# 3. Залить в новую
pg_restore -d "<новый DATABASE_URL>" --no-owner --no-acl evva.dump
```

Проверить, что доехало:

```
psql "<новый DATABASE_URL>" -c "SELECT count(*) FROM users;"
psql "<новый DATABASE_URL>" -c "SELECT count(*) FROM payments;"
psql "<новый DATABASE_URL>" -c "SELECT count(*) FROM generated_readings;"
```

Числа должны совпасть со старой базой. Пока не совпали — старую базу не трогать.

## 4. Переменные окружения

В настройках приложения на Amvera (раздел «Переменные окружения»), значения
брать из Railway:

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | токен бота |
| `DATABASE_URL` | новая база из шага 2 |
| `WEBAPP_URL` | новый адрес приложения (шаг 5) |
| `OPENROUTER_API_KEY` | основной провайдер ИИ |
| `CEREBRAS_API_KEY` | резерв |
| `GROQ_API_KEY` | резерв |
| `YOOKASSA_SHOP_ID` | оплата картой |
| `YOOKASSA_SECRET_KEY` | оплата картой |

`PORT` задавать не нужно — по умолчанию 8080, столько же в `amvera.yaml`.

## 5. Домен и Mini App

Amvera выдаёт приложению бесплатный поддомен с HTTPS — точный адрес виден на
вкладке «Инфо» проекта. Его и надо положить в `WEBAPP_URL` (без `/app` на
конце — бот добавит сам).

После смены `WEBAPP_URL` кнопка Mini App перепривязывается автоматически при
следующем старте бота (`setup_bot_commands`).

## 6. ЮKassa — не забыть

Самый опасный пункт переезда: адрес уведомлений в личном кабинете ЮKassa всё
ещё указывает на Railway. Если его не поменять, оплаты картой будут
**проходить и списываться, но разбор человек не получит** — вебхук уйдёт на
мёртвый адрес.

Личный кабинет ЮKassa → Интеграция → HTTP-уведомления:

```
https://<новый домен>/webhook/yookassa
```

Проверить живой оплатой на минимальную сумму сразу после переключения.

## 7. Проверка после запуска

- `/start` в боте отвечает;
- открывается Mini App (кнопка слева от поля ввода);
- бесплатный калькулятор числа судьбы считает;
- покупка за звёзды проходит и разбор приходит;
- покупка картой проходит и разбор приходит (пункт 6);
- в PDF заголовки блоков на месте.

Утренняя рассылка (08:00 UTC), пост в канал (07:00 UTC), опрос по пятницам и
напоминание о продлении премиума (09:00 UTC) стартуют вместе с ботом — их
видно только на следующий день.

## 8. Выключить Railway

Только после того, как всё из пункта 7 отработало. `origin` в git можно
оставить на GitHub, `amvera` — это отдельный remote для деплоя.
